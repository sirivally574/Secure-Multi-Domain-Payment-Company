# 📌 1. Project Overview

**SecurePayX** is a secure multi-domain payment company prototype developed for cybersecurity learning.

The project simulates a fintech environment containing multiple logically separated applications:

* 🌐 Main Website
* 👤 Customer Portal
* 💳 Payment Application
* 🛡️ Admin Portal
* ⚙️ Secure Backend/API

The system demonstrates how cybersecurity controls can be applied to a payment platform to protect user accounts, transactions, APIs, sessions, and administrative operations.

> **Important:** SecurePayX is an educational prototype. It does not process real money and is not connected to a real payment gateway.

---

# 🎯 2. Problem Statement

Modern payment applications handle sensitive user accounts, authentication information, transactions, and administrative operations.

Weak authentication, insecure password storage, improper authorization, unsafe input handling, insecure APIs, and insufficient monitoring can expose financial applications to security threats.

The objective of SecurePayX is to develop a secure payment platform prototype that demonstrates important cybersecurity practices across multiple application components.

---

# 🎯 3. Objectives

The main objectives of SecurePayX are:

* Implement secure user registration and authentication.
* Store passwords using secure hashing.
* Implement role-based access control.
* Protect customer and administrator resources.
* Validate payment inputs.
* Implement a basic transaction risk engine.
* Protect backend APIs.
* Manage authenticated sessions securely.
* Maintain transaction records.
* Maintain security event logs.
* Provide an administrator security dashboard.
* Demonstrate logical separation of multiple payment applications.

# 🧠 6. Transaction Risk Engine

SecurePayX contains a basic transaction risk evaluation system.

Each payment is checked for:

* Valid payment amount
* Sufficient balance
* Valid recipient
* Failed security checks

The system generates a basic risk score and determines whether the transaction should be:

```text
APPROVED
```

or

```text
BLOCKED
```

This demonstrates how a payment application can perform security checks before processing a transaction.


### User Profile API

```text
/api/profile
```

Returns authenticated user information.

### Transaction API

```text
/api/transactions
```

Returns transactions belonging to the authenticated user.

Unauthenticated requests are rejected.
